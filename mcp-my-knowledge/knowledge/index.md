# 我的开发知识库

## 提交规范

- 新增插件写完即 `git add`（暂存态），不需要提交。
- 提交只包含本次需求相关的文件，不要夹带无关改动。
- 提交说明必须写清「业务需求 + 实现方式」，不要只写「修复 bug」。

## 代码修改习惯

- 先读懂现有代码再动手，遵循项目已有风格。
- 改动范围要小，只动和需求直接相关的文件。
- 不轻易引入新依赖，优先用标准库和现有工具。

## 苍穹开发踩坑

- 报「实体类型 X/PlainObject 中不存在名为 Y 的属性」= select 漏字段，不是元数据没这个字段。路径字段的父子都要写进 select。
- BOTP 目标单上的关联对象是按映射字段裁剪的，读映射外的字段会直接报错。
- 树形基础资料用 `longnumber` 长编码逐级向上匹配，业务标准常维护在父级分类上。

## 日志

- 没说写日志就默认不写。
- 禁止在循环里写日志，失败原因走操作提示或调度回执。


## Agent Lab 命名规则

- 记录日期：2026-09-22
- 标签：agent-lab

Agent Lab 项目里，所有新建的实验脚本必须用两位数字前缀，例如 05-xxx.mjs。这是只存在于本知识库的规则。
